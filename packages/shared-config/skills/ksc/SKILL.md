# Working with @kitschpatrol/shared-config

The project lints, formats, and type checks through the `ksc` CLI. The rules are strict and warnings fail the run, so write code that matches the conventions below, then let the tools fix what they can.

## Workflow

1. Write the code.
2. Run `pnpm ksc fix`. It applies every auto-fix (formatting, sorting, import style), then reports what remains.
3. Fix the remaining issues by hand and repeat until `pnpm ksc lint` is clean.

Use pnpm, not npm, npx, or yarn. Projects usually map `pnpm lint` and `pnpm fix` to the commands above.

Both commands accept file arguments (`pnpm ksc fix src/thing.ts`) and `--skip <tool>`. Tools that only work on the whole package, such as TypeScript and Knip, ignore file arguments. To work on one tool's errors, run it alone:

| Command          | Tool                                | `lint` | `fix` |
| ---------------- | ----------------------------------- | ------ | ----- |
| `ksc-eslint`     | ESLint, including Markdown linting  | yes    | yes   |
| `ksc-prettier`   | Prettier                            | yes    | yes   |
| `ksc-typescript` | Type checking                       | yes    |       |
| `ksc-stylelint`  | Stylelint                           | yes    | yes   |
| `ksc-cspell`     | Spelling and letter case            | yes    | yes   |
| `ksc-knip`       | Unused files, exports, dependencies | yes    |       |
| `ksc-mdat`       | Readme placeholder comments         | yes    | yes   |

`pnpm ksc print-config [file]` shows the resolved configuration when a rule's settings are unclear.

## Gotchas

- **Do not sort or format by hand.** Prettier owns formatting, and the Perfectionist ESLint plugin sorts imports, object keys, type members, and unions. `fix` handles both. Some keys intentionally sort semantically instead of alphabetically (`x, y, z`, `width, height`, `min, max`, `start, end`, `r, g, b, a`), so leave whatever order `fix` produces.
- **ESLint plugins are renamed.** Disable comments must use the short prefix, e.g. `// eslint-disable-next-line ts/no-explicit-any`:

  | Upstream name                       | Prefix here       |
  | ----------------------------------- | ----------------- |
  | `@typescript-eslint`                | `ts`              |
  | `import-x`                          | `import`          |
  | `n`                                 | `node`            |
  | `vitest`                            | `test`            |
  | `@eslint-community/eslint-comments` | `eslint-comments` |
  | `@eslint-react`                     | `react`           |
  | `@stylistic`                        | `stylistic`       |
  | `jsonc`                             | `json`            |
  | `yml`                               | `yaml`            |
  | `@html-eslint`                      | `html`            |
  | `package-json`                      | `json-package`    |

- **Unknown words fail CSpell.** Add legitimate project terms to the `words` array in `cspell.config.ts`. An unscoped `ksc fix` removes words that are no longer used anywhere.
- **Knip flags anything unused**, including exports, files, and dependencies. Remove dead code instead of leaving it exported.
- **Generated readme sections are owned by mdat.** Content between `<!-- keyword -->` and `<!-- /keyword -->` comments is regenerated by `ksc fix`. Do not edit it by hand.
- **ESLint is type-aware and never cached**, so it is the slow step. `--no-cache` disables the other tools' caches if results look stale.

## TypeScript rules that fail most often

- **No `null`.** Use `undefined` (`unicorn/no-null`, `ts/no-restricted-types`). Convert at API boundaries: `apiResult() ?? undefined`. Comparing against `null` with `===` is allowed.
- **No `any`.** Use `unknown` and narrow (`ts/no-explicit-any`, plus `ts/no-unsafe-assignment`, `-call`, `-member-access`, `-return`).
- **No `Buffer` or `object` types.** Use `Uint8Array` and `Record<string, unknown>`.
- **Handle every promise** (`ts/no-floating-promises`). Use `await`, or `void someAsyncFunction()` for deliberate fire-and-forget. Functions that return a promise must be declared `async` (`ts/promise-function-async`).
- **Template literals accept only strings and numbers** (`ts/restrict-template-expressions`). Convert the rest: `` `ready: ${String(isReady)}` ``. `+` cannot mix strings and numbers (`ts/restrict-plus-operands`).
- **Conditions must be boolean** (`ts/strict-boolean-expressions`). Strings and numbers are not allowed as conditions, so write `text !== ''` and `array.length > 0` (`unicorn/explicit-length-check`). Nullable objects and nullable booleans are allowed.
- **Use `??` and `?.`** instead of `||` and `&&` chains for nullish values (`ts/prefer-nullish-coalescing`, `ts/prefer-optional-chain`).
- **Indexed access is `T | undefined`** (`noUncheckedIndexedAccess`). Narrow `array[i]` and `record[key]` before use.
- **Only erasable syntax** (`erasableSyntaxOnly`). No `enum`, runtime `namespace`, or constructor parameter properties.
- **Type-only imports and exports use separate top-level statements** (`verbatimModuleSyntax`, `import/consistent-type-specifier-style`): `import type { Foo } from './bar'` and `export type { Foo }`, never the inline `import { type Foo }`.
- **`type`, not `interface`** (`ts/consistent-type-definitions`).
- **Array types:** `string[]` for simple element types, `Array<string | number>` for anything else (`ts/array-type`).
- **Unused locals and parameters are errors.** Prefix intentionally unused ones with `_`.
- **Every code path returns** (`noImplicitReturns`), and overriding class members need `override`.

## Naming

Enforced by `ts/naming-convention` and unicorn:

- `camelCase` for variables, functions, parameters, and properties. `const` variables may also be `UPPER_CASE`.
- `StrictPascalCase` for types, classes, and type parameters. Strict means `HttpClient`, not `HTTPClient`.
- Imports and destructured variables may be `camelCase` or `StrictPascalCase`.
- Properties that need quotes (e.g. `'Content-Type'`) are exempt.
- File names are `kebab-case` (`unicorn/filename-case`).
- No abbreviations (`unicorn/name-replacements`): `error` not `err`, `button` not `btn`, `index` not `idx`. The exceptions are `i`, `j`, `acc`, `arg`, `args`, `db`, `dev`, `doc`, `docs`, `env`, `fn`, `lib`, `param`, `params`, `pkg`, `prop`, `props`, `ref`, `refs`, `sep`, `src`, `temp`, `util`, and `utils`.
- Catch clause variables are named `error` (`unicorn/catch-error-name`).

## Style

Prettier settings: no semicolons, single quotes, tabs (spaces in Markdown and YAML), trailing commas, 100 column width, LF line endings.

ESLint rules that are not auto-fixed or that change how code is written:

- Braces on every `if`, `else`, and loop body (`curly`).
- `for...of` instead of `.forEach()` (`unicorn/no-for-each`). `.reduce()` is allowed only for simple operations like sums (`unicorn/no-array-reduce`).
- `node:` protocol for Node.js built-ins: `import fs from 'node:fs'`.
- Comments start with a capital letter (`capitalized-comments`).
- Exported function declarations need a JSDoc comment with a description (`jsdoc/require-jsdoc`, `jsdoc/require-description`). Do not write types in JSDoc, so `@param name` not `@param {string} name`. `@param` and `@returns` tags are optional in TypeScript files.

## Configuration files

Each tool is configured through a typed factory function. Pass overrides to the factory instead of replacing the shared config:

| File                  | Contents                                                      |
| --------------------- | ------------------------------------------------------------- |
| `eslint.config.ts`    | `eslintConfig()` from `@kitschpatrol/eslint-config`           |
| `prettier.config.ts`  | `prettierConfig()` from `@kitschpatrol/prettier-config`       |
| `cspell.config.ts`    | `cspellConfig()` from `@kitschpatrol/cspell-config`           |
| `knip.config.ts`      | `knipConfig()` from `@kitschpatrol/knip-config`               |
| `stylelint.config.js` | `stylelintConfig()` from `@kitschpatrol/stylelint-config`     |
| `.remarkrc.js`        | `remarkConfig()` from `@kitschpatrol/remark-config`           |
| `mdat.config.ts`      | `mdatConfig()` from `@kitschpatrol/mdat-config`               |
| `tsconfig.json`       | `"extends": "@kitschpatrol/typescript-config"` (TypeScript 6) |

Configs may instead live under the matching keys in `package.json`. `eslintConfig()` detects Astro, React, and Svelte from installed packages. Pass `{ astro: true }`, `{ react: true }`, or `{ svelte: true }` to force one on. Per-file rule overrides go in the factory's options, e.g. `eslintConfig({ ts: { overrides: { 'ts/no-explicit-any': 'off' } } })`.
